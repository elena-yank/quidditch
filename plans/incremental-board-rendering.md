# Инкрементальный рендер поля (устранение лагов при большом числе игроков)

## Проблема

Поле полностью перерисовывается при каждом опросе сервера (каждые 2 секунды,
`startRoomPolling` → `refreshRoomOnce` → `renderRoom`).

Внутри `renderRoom` функция `renderBoard()` делает
`els.pitch.innerHTML = ""` и заново создаёт **все клетки** сетки (13×13),
а `renderPieces()` / `renderQuaffle` / `renderBludgers` / `renderSnitch`
пересоздают **все фишки, мячи и снитч**.

С ростом числа игроков/наблюдателей растёт число DOM-узлов, которые
создаются и выбрасываются каждый тик — отсюда лаги.

## Цель

Не перерисовывать то, что не изменилось:
- Сетка поля строится **один раз** и живёт как статичный слой.
- Фишки, мячи и снитч **перемещаются/переиспользуются**, а не пересоздаются
  (DOM-узел переносится через `appendChild`, что дёшево).
- Меняются только классы подсветки и точечные изменения, как и раньше.

Вся игровая логика, подсветки, делегирование кликов на `els.board.onclick`,
права ходов и интерфейс остаются прежними — меняется только способ обновления DOM.

## Подход

Сетка поля статична и одинакова для всех комнат (`els.pitch` постоянен в DOM).
Поэтому можно строить её один раз и переиспользовать между комнатами.

Для фишек ведём реестр `Map<participantId, element>`:
- новая фишка — создаём;
- существующая — обновляем классы/текст/бейдж и **переносим** в нужную клетку;
- исчезнувшая — удаляем.

Для мячей и снитча (их фиксированное количество: 1 квоффл, до 2 бладжеров,
1 снитч) — аналогичная реконсиляция.

Порядок внутри клетки сохраняем: сначала мячи, затем фишки (`appendChild`
в `reconcilePieces` всегда ставит фишку наверх, как в исходном коде).

## Изменения

### `public/app.state.js`
- Добавить поля состояния:
  - `boardBuilt: false`
  - `pieceEls: new Map()` — реестр фишек по `participantId`
  - `itemEls: { quaffle: null, bludgers: [], snitch: null }` — реестр мячей/снитча

### `public/app.ui.js`
- `renderBoard()` → `buildBoardOnce()`:
  - если `state.boardBuilt` уже true — выходим (не очищаем и не пересоздаём);
  - иначе строим сетку один раз и ставим флаг.
- Новые хелперы реконсиляции:
  - `reconcilePieces(gameState, pieces)` — инкрементальная отрисовка фишек;
  - `reconcileItemEls(gameState)` — квоффл, бладжеры, снитч;
  - `reconcileSingleItem(existing, cls, coord)` и `reconcileListItems(...)`.
- В `renderPieces()` заменить цикл создания фишек (строки ~1245–1267) на вызов
  `reconcilePieces(...)`; логика подсветки и `clearBoardSelection` остаётся.
- В `renderRoom()` заменить `renderBoard()` на `buildBoardOnce()`,
  а `renderQuaffle/renderBludgers/renderSnitch` — на `reconcileItemEls()`.

### `public/app.main.js`
- В `resetRoomScopedState()` добавить сброс игровых слоёв:
  - очистить `state.pieceEls` и `state.itemEls` (удалить элементы из DOM);
  - сбросить `state.boardBuilt = false` (чтобы сетка перестроилась при входе).

## Что НЕ меняется
- Сервер и API (`src/*`) — без изменений.
- Игровые правила, подсветки целей, клики по доске, дуэли, чат, голос.
- Логика `renderBoardSnapshotToCanvas` (строит свою канву из state).

## Ожидаемый результат
- Сетка поля перерисовывается только один раз за сессию.
- При каждом тике меняются лишь реально изменившиеся фишки/мячи и подсветки.
- Нагрузка перестаёт расти линейно с числом игроков на каждую перерисовку.
